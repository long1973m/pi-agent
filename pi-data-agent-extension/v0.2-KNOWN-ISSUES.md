# v0.2 已知问题清单

> 日期：2026-07-02
> 严重度定义：P0 阻塞发布 / P1 必须修复 / P2 建议修复 / P3 低优先级

---

## P1（建议在 v0.3 前修复）

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 1 | 数据字典缺少用户确认环节（`ctx.ui.confirm()`） | `src/hooks/data-dictionary.ts` | 字典自动生成标记 ai-guessed，用户无法修正。Spec 要求 LLM 推断 + 用户确认 |
| 2 | 查询记忆淘汰公式与 Spec 不符 | `src/hooks/query-memory.ts` | 当前线性衰减 `useCount × 1/(1+daysAgo)`，Spec 要求 `log(useCount+1) × exp(-recency/7天) × relevanceScore` |
| 3 | `buildCountSql()` 正则可能误删子查询 LIMIT | `src/engine/duckdb.ts` | 正则只匹配末尾 LIMIT，子查询中的 LIMIT 可能被误删 |

## P2（不阻塞，建议 v0.3 修复）

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 1 | agent.md 实际是 JSON 格式 | `src/persistence.ts` getAgentMdPath() | 文件名 `.md` 但内容是 JSON，命名有误导性 |
| 2 | Hook 事件名与 Spec 不符 | `src/hooks/active-questioning.ts` | `tool_call` vs Spec 的 `beforeToolCall`，功能等效，已文档化 |
| 3 | Python 脚本路径硬编码 | `src/tools/visualize.ts` | `join(__dirname, "..", "..", "scripts", ...)` 项目结构变化时失效 |
| 4 | overview.sql/cleaning-checks.sql 含 Jinja2 语法 | `skills/data-exploration/scripts/` | 部分查询需要模板引擎渲染，不能直接在 DuckDB 中执行 |
| 5 | `QueryMemoryEntry` 缺少 `relevanceScore` 字段 | `src/types.ts` | 影响淘汰公式精度 |
| 6 | 无 Python requirements.txt | 项目根目录 | 无 Python 依赖版本锁定文件 |
| 7 | `poc_dummy` 工具未改为可选 | `src/index.ts` | 可能被 Agent 误用测试工具 |
| 8 | `UPDATE` 正则匹配所有 UPDATE 语句 | `src/security.ts` | 当前匹配所有 UPDATE，意图是仅检测无 WHERE 的 UPDATE |
