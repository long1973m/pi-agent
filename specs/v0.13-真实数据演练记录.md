## 4. 发现清单

| # | 发现 | 严重度 | 去向 |
|---|---|---|---|
| F1 | **文件不存在被误报为"不是有效的 Excel 文件"**：`readMagicBytes` 把 ENOENT 等 open 错误归入 null，`prepareExcelSource` 一律报文件头校验失败（演练首跑即踩中） | 中 | BACKLOG 小修：区分"文件不存在"与"格式不符" |
| F2 | **read_csv_auto 日期嗅探对真实导出脆弱**：xlsx→CSV 后 `12/13/10 9:02` 混合格式 TIMESTAMP 嗅探失败整表拒绝；load_data 无 types/dateformat 逃生参数 | 中 | BACKLOG：load_data 增加 read_csv_auto 选项透传；当前 workaround = 预处理 ISO 日期（本演练即用）|
| F3 | **字段语义规则推断粗糙**：Country（VARCHAR 维度列）被推断为"数量"；InvoiceNo/StockCode"未知语义"——ai-guessed 误导的实证 | 中 | ✅ 已回流字典（6 列 user-corrected）；佐证 v0.10 §9 字典 AI 推断重做欠账；**模板列映射必须显式传参，不得信自动推断** |
| F4 | **engine 类型映射缺 HUGEINT**：查询输出阶段告警"Unknown DuckDB type: HUGEINT, defaulting to VARCHAR"（COUNT/SUM 聚合常见类型） | 低 | 阶段二 TPL-1 开工前顺手修（模板 sanity check 要消费类型）|
| F5 | **手写 cohort SQL 语义陷阱（本次最有价值发现）**：`SUM(CASE WHEN ym>cohort THEN 1 END)` 统计的是"活动月数"而非"复购客户数"，产出 449.1% 的荒谬留存率——结果看似合理、无任何机制拦截 | 高 | cohort 模板确定性实现 + sanity 范围护栏（留存率 ∈ [0,100]）的直接证据；正确口径 `COUNT(DISTINCT CASE WHEN ... THEN CustomerID END)` 固化为 golden 断言 |
| F6 | 订单流水无阶段/事件列，真实多阶段漏斗需要事件型数据；"取消"是反向指标而非漏斗阶段 | 中 | 模板 condition-based 设计正确（spec 不变）；method_notes 写明"状态互斥数据不适用漏斗模板，用分组对比" |
| F7 | A/B 参数映射真实可行：version 恰 2 值、retention_1 布尔、userid 为 unit；SQL 算 z 可行、p 值必须 TS | — | spec 参数设计确认，无需修改 |
| F8 | SheetJS 转换 541k 行 Excel 耗时 ~12s，可接受；大数据量建议 CSV | 低 | README D-1 提示 |

## 5. 对模板设计（阶段二/三）的结论

1. **TPL-2 funnel**：参数设计不变（steps 条件叠加 + user_key + 可选窗口）；新增注意点——method_notes 必须说明"阶段条件应为递进关系（合取）"，状态互斥型数据（如订单 status）不适用，模板可加 soft warning"后一步人数 > 前一步"（spec 已含）。
2. **TPL-3 cohort**：参数确认（user_key / activity_time / period / activity_condition 可选）；F5 陷阱固化为 golden 断言与 [0,100] 范围护栏；本数据集的正确演练口径应排除退货（Quantity > 0）——activity_condition 参数的存在价值被实证。
3. **AB-1**：参数与统计口径全部确认；z 可由 SQL 确定性计算，p 值按 §0.3 核验结论走 TS 正态 CDF；真实数据复算结果（z=1.0361，不显著）与公开分析一致，作为 golden 之外的佐证记录。
4. **TPL-1 通用**：模板返回的映射清单（user_key/时间列/成功条件）必须回显，防止 F3 式语义错位；类型消费前先修 F4。
