# Pi Data Agent v0.12 执行 Spec｜外部数据库连接阶段 1：MySQL 只读 ATTACH + 多方言安全基座

<aside>
🔧

版本定位：v0.12 = 数据库连接阶段 1（v0.2 起最长欠账的首次落地）。范围来自 2026-08-30/31 两轮调研（`research/database-connection-research.md`、`research/other-database-support-research.md`，结论已入库 commit 701209a / 150f496）。技术路线已定：**DuckDB 原生 mysql 扩展 + ATTACH，不用 MCP、不用直接驱动**。本版本只做阶段 1（MySQL 只读）+ 多方言抽象基座 + SQLite 离线脆弱点修复；物化（阶段 2）与 PostgreSQL（阶段 3）分别留给 v0.13 / v0.14。

Dashboard 删除表能力已先行交付（commit 4a378f0，v0.12 首个功能）。

</aside>

> **核心目标**：① `connect_database` 从"仅 sqlite 文件"扩展为"sqlite 文件 + MySQL 只读远程"，且远程路径在白名单、凭据、超时、SQL 拦截四层全部 fail-closed；② 从第一天就按 `RemoteDbDialect` 多方言结构实现，PG 接入（阶段 3）降级为"填一张配置表 + 对称测试"；③ 修掉 SQLite 依赖扩展自动下载的离线脆弱点（与 MySQL 同源隐患）。
>
> **安全红线（贯穿全部任务）**：密码不进 LLM context、不进审计日志、不进 `.duckdb` 文件；`dbAllowedHosts` 默认空 = 拒绝一切远程连接（现有纯本地用户行为零变化）；模型不得自行发起 ATTACH。

## 0. 前置状态与实施前检查

基线（2026-08-31）：52 文件 / 317 用例全绿，`tsc --noEmit` 零错误，工作树干净，main 分支 17 commits（无 remote）。

调研已实测的关键事实（详情见 `research/database-connection-research.md` §4）：

- 明文连接串 ATTACH 失败时**异常文本含明文密码**（§4.5 实测）；secret 方式不含 → **强制 secret 路线**
- `mysql_query_timeout_max_ms` 默认 300000 已开启；PG 侧 `pg_statement_timeout_millis` 默认 null（阶段 3 必须显式设，本版本只需在 dialect 表里留位）
- pushdown 默认开启（`count(*)` 在远端算）
- `READ_ONLY` 是客户端约束，服务端只读账号才是真边界（文档要求用户 `GRANT SELECT ONLY`）
- 扩展二进制 29 MB（gz 10 MB），首次 INSTALL 需联网约 4 秒；现有 sqlite 路径依赖自动安装/自动加载，离线即失败

### 0.1 开发前必须核验

- [ ] `@duckdb/node-api` 1.5.4 下 `engine.exec("INSTALL mysql")` / `LOAD mysql` 是否可用（调研实测走的是 DuckDB CLI，node-api 同引擎应成立，但要跑通一次真实 INSTALL→LOAD→CREATE SECRET→ATTACH 全链路）
- [ ] `CREATE SECRET (TYPE mysql, HOST.., PASSWORD..)` + `ATTACH '' AS x (TYPE MYSQL, SECRET name, READ_ONLY)` 在 node-api 下的行为与 CLI 一致

## 3. M-2：`checkRemoteTarget` 远程目标白名单（P0）

### 3.1 方案要点

`src/security.ts` 新增独立入口（不塞进 `checkSql`，职责分离）：

```ts
checkRemoteTarget(host: string, port: number): SecurityCheckResult
```

- 匹配规则：`dbAllowedHosts` 逐条比对——条目含 `:port` 时要求 host+port 同时命中；仅 `host` 时任意端口命中
- host 归一化：大小写不敏感；`localhost` 与 `127.0.0.1` **不视为等价**（写哪条算哪条，避免隐式扩权）
- fail-closed 语义沿用 `resolveConfirmGate` 三态：白名单外一律 **block**（不是 confirm——远程连接没有"顺手确认"的合理性）
- 错误文案必须包含当前白名单内容，指导用户如何配置（改 env 或 config.json）

### 3.2 验收标准

- [ ] 默认配置下任何 host 均返回 block，reason 含白名单配置指引
- [ ] `host:port` 条目端口不匹配时 block；仅 `host` 条目任意端口放行
- [ ] 大小写归一化生效；`localhost` ≠ `127.0.0.1`

## 4. M-3：SQL 层拦截模型自行 ATTACH（P0）

### 4.1 根因

`READ_ONLY` 只是客户端约束——模型能看到工具描述与系统提示里的 SQL 语法，完全可以在 query_data 里自己发一条不带 READ_ONLY 的 `ATTACH 'host=.. password=..' (TYPE MYSQL)`。`classifySql` 现有读写分类**不覆盖 ATTACH**。

### 4.2 方案要点

- `security.ts` 的 `classifySql` 新增：语句含 `\bATTACH\b` 或 `\bDETACH\b` → 直接返回 `"dangerous"`（block），**无例外**
- 工具内部构造的 ATTACH（connect_database / 后续物化）走 `engine.exec`，不经过 `checkSql`，不受影响——这是刻意设计：ATTACH 只允许出现在工具实现层
- 验收必须包含「模型侧绕过样本」：`ATTACH 'host=x' AS y (TYPE MYSQL)`、多行/注释夹带的 ATTACH、`autoConfirmWrite=true` 时**仍然 block**（dangerous 级不受自动确认豁免，需在 checkSql 中保证 dangerous 分支先于 autoConfirmWrite 判定——现实现 §165 行顺序已如此，补断言防回归）

### 4.3 验收标准

- [ ] query_data 执行任意 ATTACH/DETACH 返回 blocked
- [ ] `autoConfirmWrite=true` 不豁免 ATTACH block
- [ ] connect_database 正常 ATTACH 路径不受影响（全量回归绿）

## 5. M-4：`RemoteDbDialect` 抽象 + `attachRemote()`（P0，多方言基座）

### 5.1 方案要点

`src/engine/duckdb.ts` 新增（或独立 `src/engine/remote-dialect.ts`，实施时按文件体量决定）：

```ts
interface RemoteDbDialect {
  type: "mysql" | "postgres";        // v0.12 只注册 mysql；postgres 留结构位
  extensionName: string;             // "mysql"
  secretType: string;                // "mysql"
  settingsPrefix: string;            // "mysql"
  defaultPort: number;               // 3306
  timeoutSetting: string;            // "mysql_query_timeout_max_ms"
}
const REMOTE_DIALECTS: Record<string, RemoteDbDialect>  // 阶段 3 加 postgres 一行 + 测试
```

`attachRemote(spec)` 封装固定顺序（每一步失败都要清理半成品 secret）：

1. **显式 INSTALL + LOAD**：`INSTALL {extensionName}` → `LOAD {extensionName}`；失败时返回降级指引文案（离线环境：预置 `~/.duckdb/extensions/v1.5.4/osx_arm64/` 或设置 `extension_directory`），不再依赖静默自动下载
2. **CREATE SECRET**：temporary secret（不落盘），连接参数只用 host/port/database/user，**password 来自凭据解析层（M-5），永不拼进 ATTACH 串**
3. **ATTACH ''**：`ATTACH '' AS {alias} (TYPE {dialect.type}, SECRET {name}, READ_ONLY)`
4. **超时**：`SET {dialect.timeoutSetting} = {config.dbQueryTimeoutMs}`
5. 返回 attach 结果句柄（alias、dialect、连接摘要——host:port/db，**无凭据**）

禁止使用的路径（写死在实现与 code comment）：`mysql_query()`（issue #65 DECIMAL 全 NULL）、明文连接串 ATTACH。

### 5.2 验收标准

- [ ] 对不通端口执行 attachRemote：抛出的错误文本经 redact 后不含任何凭据（T-1 断言）
- [ ] secret 创建失败 / ATTACH 失败时，temporary secret 无残留（重连同名 alias 不冲突）
- [ ] INSTALL 失败（模拟：`SET extension_directory` 指向空目录 + 断网不可模拟时用注入假 extension 名）返回降级指引文案

## 6. M-5：`connect_database` 重构（P0）

### 6.1 参数设计（向后兼容）

现有调用（sqlite + file_path）行为完全不变。`db_type` 扩为 `"sqlite" | "mysql"`，mysql 分支新增参数：

| 参数 | 说明 |
|------|------|
| `host` | 必填 |
| `port` | 可选，默认 3306 |
| `user` | 必填 |
| `database` | 必填 |
| `alias` | 可选，默认 `{database}_{host}` 归一化；冲突时报错要求显式指定（不做静默 DETACH 换连） |

**参数 schema 里禁止出现 password 字段**——工具参数会整体进 LLM context，密码参数本身就是泄漏点。

### 6.2 凭据解析顺序（fail-closed）

1. env `MYSQL_PWD`（DuckDB 扩展原生识别，用户现有习惯零迁移）
2. env `PI_DATA_AGENT_MYSQL_PWD`（项目命名空间，避免与用户 shell 里指向其他用途的 MYSQL_PWD 冲突——两者都设时本项目 env 优先）
3. 交互模式下 `ctx.ui` 输入（结果仅存入 temporary secret）
4. 全部缺失 → block，文案说明三种配置方式

密码只进 `CREATE SECRET` 语句，该语句的执行结果与错误信息**不进**任何返回文本（见 M-6）。

### 6.3 执行流

1. `db_type` 分流 → mysql 分支：`security.checkRemoteTarget(host, port)` block 即止
2. 凭据解析（§6.2）
3. `attachRemote(spec)`（M-4）
4. 枚举表与 schema（复用现有 alias 三级 fallback 查询逻辑，抽成私有函数与 sqlite 共用）
5. 返回文本：连接摘要（host:port/db、表数、示例 SQL）+ **只读声明**（"本连接强制 READ_ONLY；服务端请使用 GRANT SELECT ONLY 账号"）

### 6.4 验收标准

- [ ] sqlite 路径全量回归绿（行为零变化）
- [ ] 白名单外 host → block，文案含配置指引
- [ ] 无凭据 headless 环境 → block，文案含三种配置方式
- [ ] 对不通端口的完整执行：返回错误不含密码；audit 日志不含密码（M-6 联合验收）
- [ ] 成功 ATTACH 后 query_data 可 `SELECT * FROM alias.tbl LIMIT 10`（真机手动验收，见 §12）

## 14. 风险与注意事项

| 风险 | 说明 | 对策 |
|------|------|------|
| 密码进 context（最高风险） | 工具参数、错误文本、审计日志三个泄漏面 | 参数 schema 无 password 字段 + 强制 secret + redact 兜底 + T-1 #7 结构断言，四层防线缺一不可 |
| `classifySql` 加 ATTACH 后误伤 | 未来某工具可能合法需要 ATTACH 本地文件 | 设计定死：ATTACH 只允许出现在工具实现层（engine.exec 直达）；新需求走新工具，不走模型 SQL |
| INSTALL 联网失败 | 离线/受限网络直接失败 | 显式 INSTALL + 降级指引文案；预置扩展路径写入指引 |
| alias 冲突处理变化 | sqlite 现状是静默 DETACH 换连；mysql 改为报错要求显式指定 | 行为变化仅发生在显式重名场景；sqlite 分支保持现状不动，差异写入工具描述 |
| `MYSQL_PWD` 语义冲突 | 用户 shell 里可能已有指向其他用途的 MYSQL_PWD | 双 env 设计（§6.2），项目 env 优先；README 说明 |
| community 扩展版本配对 | 本版本只用 core 扩展（mysql/sqlite），无此风险 | 提前写入 BACKLOG 备注：升级 @duckdb/node-api 前核对扩展源（对应 other-database-support-research §3） |
