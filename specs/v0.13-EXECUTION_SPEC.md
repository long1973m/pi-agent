> **核心目标**：① L2 即时注入（v0.10 §9.1 设计原样落地）——模型从"猜口径"变成"引用口径"；② 新工具 `run_analysis_template`——漏斗 / cohort / A/B 三种参数化模板，一次调用产出确定性统计结果；③ 结果 sanity check——模板输出前确定性校验，异常以结构化警告/错误呈现，绝不产出"看似合理的编造"。
>
> **三条红线（贯穿全部任务）**：
> 1. **统计红线**：一切数值结论（转化率、留存率、z、p、显著性判定）由确定性代码（DuckDB SQL / TypeScript）计算；LLM 只解释数值，不产生数值。模板结果必须携带固定的"方法与局限"小节。
> 2. **只读红线**：模板生成的 SQL 只允许 SELECT，且必须复用 query_data 既有执行路径与安全拦截（黑名单 / 超时 / 大结果 spill / 错误恢复 / 审计），**不开新执行通道**。
> 3. **字典红线**：模板参数映射到 `uncertain` 状态列 → 直接拒绝执行（fail-closed）；映射到 `ai-guessed` 列 → 结果携带 ⚠ 警告。统计建立在含义不明的列上比没有统计更糟。

### 0.2 关键设计决策

1. **统计确定性红线**（本版本灵魂）：显著性、样本量护栏、辛普森悖论扫描全部写成确定性函数；LLM 的职责边界 = 拿到结构化结果后写解释。原因：模板最危险的故障模式是"悄悄算错但看起来像模像样"，LLM 心算 p 值是不可接受的。
2. **模板执行复用 query_data 内核**：模板生成 SQL 后走与 query_data 相同的执行函数（拦截 / 超时 / spill / error-recovery）。若该内核与工具壳耦合，先做最小抽取重构（行为零变更，355 用例保护）。不开第二条执行通道，安全模型不扩面。
3. **L2 按已定稿设计落地，内容收敛为三类**：触发条件、已交付清单、预算照 v0.10 §9.1。附注内容 = 表卡片 + 指标口径 + uncertain 字段警示。原设计的"历史样例附注"轻量扩展在实施时**撤除**（v0.13.1）：代码盘点发现 L0 Query Memory（`generatePromptInjection`）已每轮向 system prompt 注入最多 3 条相关问答，L2 再附注属重复投喂。Query Recipe 全链路（检索 / 验证 / 失效 / 晋升状态机）仍挂 BACKLOG，本版本不建。
4. **v1 模板范围刻意收窄**：漏斗只做"状态漏斗"（同表条件叠加计数），事件序列漏斗推迟；A/B 只做双臂双比例 z 检验。先让三把刀真的快，再考虑多功能刀。
5. **S0 真实数据演练是模板参数定稿的门**：用户 PM 工作的真实导出数据（CSV/Excel）先跑现有流程，摩擦点决定模板参数设计；避免闭门造出一套"技术漂亮但与日常不贴"的模板。

### 0.3 开发前必须核验

- [x] DuckDB `normal_cdf` **不可用**（@duckdb/node-api 1.5.4-r.1 实测 Catalog Error，2026-09-27）→ 阶段三 AB-1 的 p 值计算直接走 TypeScript 确定性正态 CDF（Abramowitz-Stegun，误差 < 1e-7），不依赖 DuckDB 统计函数

## 3. 阶段一：L2 即时注入（P0）

### 3.1 L2-1：已交付清单与开关

- session 级内存 `Set<string>`，键格式：`tableCard:<表名>@<fingerprint>`、`metric:<id>`、`historySample:<entryId>`
- 写入时机：L2 附注发生时；get_table_card 成功返回时（L2-4）
- 重置时机：新会话自然为空（runtime 在 session_start 重建）；表 fingerprint **内嵌在键中**，结构变化（重新加载且结构变了）键自然失配 → 自动重投递，无需显式重置；pi 无扩展可见的 compaction 事件（§0.3 核验结论），压缩后不做重置
- config：`l2InjectionEnabled`（默认 `true`）+ ENV `PI_DATA_AGENT_L2_INJECTION`（`off`/`false`/`0` 关闭）——噪音逃生阀，关闭后 L2 完全静默

验收：

- [ ] 键写入 / 查重 / 重置行为符合上述语义；fingerprint 变化后同表重新附注
- [ ] 开关关闭时 query_data 返回与现版本逐字节一致（除既有内容外零新增）

### 3.2 L2-2：提示类附注（本阶段核心）

- **注入点**：query_data 工具内部，执行完成后拼接在结果前（v0.10 §9.1 优先方案；备选 tool_result 增强，仅在工具内实现有障碍时启用并记录）
- **触发四条件**（照 §9.1，全部满足）：① 目标识别——FROM/JOIN 词法提取 + 与已登记表名**精确匹配**（不做 SQL AST），或 user_intent 命中已定义指标名；② 知识存在——表有卡片（含 stale）、命中指标定义、或 SQL 触及 uncertain 字段；③ 未交付——已交付清单查无；④ 预算内
- **附注组装优先级**（预算内从上往下装；超预算整行放弃，其键不标记已交付，下次仍可交付）：
  1. 表卡片提醒：summary 一句 + boundaries 前 2 条；stale 卡片注明"已过期，建议 get_table_card"
  2. 指标口径：user_intent 命中的指标 ≤2 条，格式"名称 = 一行定义"
  3. uncertain 字段警示：SQL 触及的 uncertain 状态列，格式"字段 X 语义未确认（uncertain），相关分析结果可信度受限"
  （历史样例已撤除——L0 Query Memory 已覆盖，见变更记录 v0.13.1）
- **预算**：单次附注 ≤200 token（字符数近似断言，同 A-4 测试法）；每轮 ≤2 张表
- **语义**：附注是提醒不是拦截，文案示例——`📋 语义附注（自动）：ecommerce_orders 表边界：仅含 2026-06 样例数据；口径：GMV = 已支付订单金额求和`

### 3.3 L2-3：冲突类拦截（P1，保守）

仅当三者同时成立：user_intent 点名某指标 + SQL 聚合该指标的度量列 + 缺失指标定义中明确写有的过滤条件 → 复用 active-questioning 拦截机制，附定义原文让模型改写后重新提交。**宁可漏拦不可误拦**；无把握一律走提示类。

### 3.4 L2-4：get_table_card 联动

get_table_card 成功返回表 X → 已交付清单写入 `tableCard:X@fp` 与该表关联的 metric ids（按 metrics.datasets 关联），避免同一信息对模型交付两次。

- [x] 有卡片的表查询后，结果含附注且 ≤ 预算（800 字符 ≈ 200 token）；同表第二次查询不重复附注
- [x] user_intent 命中指标 → 附口径行；SQL 触及 uncertain 列 → 附警示行
- [x] get_table_card 之后同表不再附注（卡片与关联指标键均已标记）
- [x] 开关关闭时完全静默（`PI_DATA_AGENT_L2_INJECTION=off`）

## 4. 阶段二：PM 模板包——funnel / cohort（P0）

### 4.1 TPL-1：`run_analysis_template` 工具骨架

> **实现前置（S0 发现 F4）**：先修 engine 类型映射缺 HUGEINT 的问题（`Unknown DuckDB type: HUGEINT, defaulting to VARCHAR`，COUNT/SUM 聚合常见类型），模板 sanity check 依赖类型消费。

**参数**

| 参数 | 必填 | 说明 |
|------|------|------|
| `template` | ✅ | `funnel` / `cohort` / `ab_test` |
| `table` | ✅ | 已登记数据集（main 库表）。远程 attached 表 v1 不支持 → 明确报错并指引：先物化（v0.14）或 load_data 导入 |
| `params` | ✅ | 各模板专属参数，见 §4.2 / §4.3 / §5.2 |
| `user_intent` | ✅ | 沿用 query_data 惯例（审计与口径匹配依赖它） |

**执行流（五步）**

1. **校验**：表已在 list_datasets 登记；params 涉及列存在且类型合理（DESCRIBE + data-profile）；字典状态——`uncertain` 列 → **block**（fail-closed，文案指引 confirm_dictionary）；`ai-guessed` 列 → 警告标记进返回
2. **SQL 生成**：确定性模板函数产出 SQL（v1 仅内置三模板，不开放自定义模板注册）；生成语句先过 security 既有校验（黑名单 / 只读），`params.condition` 只允许作为 WHERE 布尔表达式嵌入
3. **执行**：复用 query_data 内核（同一拦截 / 超时 / spill / error-recovery）
4. **确定性计算**：统计量在 TS/DuckDB 内完成；AB-2 sanity 统一后处理（§5.1）
5. **返回结构**：`{ data_rows, metrics, warnings[], method_notes, chart_suggestion, dictionary_flags }`——`method_notes` 为固定"方法与局限"小节；解释性叙述由模型基于该结构生成，**数值禁止改写**

**审计**：`AUDIT_TOOLS` 加入本工具；`AuditLogManager.buildSummary` 新增 case（template / table / params 摘要 — result）。

### 4.2 TPL-2：funnel 模板（状态漏斗 v1）

**params**

| 参数 | 说明 |
|------|------|
| `steps[]` | 2–8 步，数组序即漏斗序；每步 `{ label, condition }`，condition 为该表 WHERE 布尔表达式 |
| `user_key` | 去重键列（用户 ID / 订单 ID，语义由调用者声明并进结果映射清单） |
| `time_column` + `window_days` | 可选，成对出现；限定分析窗口 |

**语义**：窗口（默认全表）内第 k 步人数 = 满足前 k 步条件**合取**的 distinct user_key（状态漏斗 = 条件叠加）。输出：每步人数、步间转化率、总转化率。

**v1 明确不做**（Deferred）：事件序列漏斗（步序时间约束，"先 A 后 B"）、步间耗时分析。S0 若证明真实数据是事件型，先改本 spec 再实施。

### 4.3 TPL-3：cohort 模板（留存三角）

**params**：`user_key`、`activity_time`（时间列）、`period: week|month`、`activity_condition?`（布尔，可选）、`lookback`（默认 12，上限 24）。

**语义**：按 `date_trunc(period, activity_time)` 首次活跃分群；第 N 期留存 = 该群在 first_period + N 期仍活跃的 distinct user_key 占比。输出：三角矩阵（群 × 期偏移）、各期平均留存。

### 阶段二验收（2026-09-27 已完成）

- [x] golden funnel（§6.1）：三步 10 / 6 / 3 人，步间 60% / 50%，总转化 30% 精确断言
- [x] golden cohort：两群月度留存 100/60/30% 与 100/50% 精确断言（均值 55% / 30%）
- [x] 非递进处理：**设计修订**——累计合取语义下"后步人数 > 前步"结构上不可能，原 soft warning 升级为 sanity 不变量硬错误（触发即报告模板 bug）；"最后一步人数为 0"保留为 soft warning
- [x] `ai-guessed` 列 → dictionaryFlags 标记；`uncertain` 列 → block（fail-closed，含 confirm_dictionary 指引）；缺列 → 执行前预校验 `missing_column` 结构化错误（含可用列清单）
- [x] 模板 SQL 全程只读：构造含写语句成分的 condition → 拦截/执行失败且表完好
- [x] audit.log 出现 run_analysis_template 记录（AUDIT_TOOLS + buildSummary case）

## 5. 阶段三：A/B 解读与结果 sanity（P0）

### 5.1 AB-2：sanity check 共用组件

三模板统一后处理，两级分诊，**禁止静默吞掉**：

| 级别 | 判定 | 行为 |
|------|------|------|
| hard | 表 / 列缺失、查询行数为 0、时间窗为空 | 结构化 error，不输出统计叙述 |
| soft | 漏斗非递进；A/B 任一臂转化数为 0 或全转化（无法检验）；lookback 超出数据范围；p ∈ (0.01, 0.2) 边缘显著提示 | warnings[] 字段随结果返回 |

### 5.2 AB-1：ab_test 模板（双比例 z 检验）

**params**

| 参数 | 说明 |
|------|------|
| `variant_column` | 必须恰好 2 个非空取值，否则参数错误 |
| `success_condition` | 转化布尔条件 |
| `unit` | 去重粒度（user_key / 订单粒度），去重语义进结果映射清单 |
| `segment_columns[]` | 可选，≤3 列；Simpson 悖论扫描用 |
| `alpha` | 默认 0.05 |

**统计口径（写死，README 同步公开）**：

- 双侧两比例 z 检验：z = (p₂−p₁) / √( p̂(1−p̂)(1/n₁+1/n₂) )，p̂ 为合并比例；p = 2·(1 − normal_cdf(|z|, 0, 1))（DuckDB 计算；精度核验不过关则换 TS 确定性实现，见 §0.3）
- **护栏（全部确定性输出，不是 LLM 判断）**：
  1. 样本量：任一臂 n < 100 或 min(n·p̂, n·(1−p̂)) < 5 → "样本不足"标记
  2. Simpson：按 segment_columns 逐段重算方向，任一段方向与总体相反 → 悖论警告
  3. 边缘显著：p ∈ (0.01, 0.2) → "谨慎下结论"提示
  4. 效应量：绝对差 + 相对 lift 一并输出
- `method_notes` 固定写明适用条件：独立双组、双尾、大样本正态近似；不满足时结论不可靠

### 阶段三验收（2026-09-28 已完成）

- [x] golden A/B（1000/100 vs 1000/130）：|z − 2.103| < 0.01、|p − 0.0355| < 0.005、α=0.05 判定显著（实测 z≈2.1032、p≈0.03545）
- [x] golden 小样本（50/5 vs 50/7）：不显著（p≈0.5383）+ 两臂"样本量 < 100"护栏
- [x] golden Simpson 数据：总体 treatment 优（9.1% vs 3.8%）但两段内均 control 优 → 2 条悖论发现 + 风险警告
- [x] variant_column 出现第三取值 → invalid_params；三模板返回均含 method_notes
- [x] 退化臂（全转化）→ "无法检验"提示；alpha 覆盖生效（α=0.01 时 p=0.0355 不显著）；边缘提示锁定（p=0.0355 ∈ (0.01, 0.2)）
- [x] p 值由 TS 确定性正态 CDF（Zelen–Severo，|ε|<7.5e-8）计算——§0.3 核验结论的落地
