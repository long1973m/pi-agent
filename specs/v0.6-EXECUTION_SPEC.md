# Pi Data Agent v0.6 执行 Spec｜Dashboard + 数据字典可视化维护（修订版）

<aside>
🖥️

版本定位：v0.6 = 本地 Web Dashboard。统一承载历史分析成果浏览、数据字典维护、数据预览、图表画廊、SQL 历史与口径管理。TUI 继续负责分析交互，Dashboard 负责成果浏览和元数据管理。

> 

> 

> **范围决策**：保留完整功能范围，不把数据预览、列统计、图表画廊、SQL 历史、会话报告入口和口径管理拆到后续版本；通过明确 P0/P1 实施顺序控制风险，而不是删除功能。

## 1. 产品目标与范围

### 1.1 用户目标

用户打开 Dashboard 后，应能完成六类任务：

1. **浏览分析成果**：按时间查看历史 Session 报告，并打开完整消息流、图表和 SQL。
2. **管理数据字典**：查看表与字段，编辑业务含义、确认状态和备注。
3. **检查数据内容**：预览数据集前 N 行并查看基础列统计。
4. **浏览历史图表**：跨报告查看图表缩略图，并回到图表所属报告理解上下文。
5. **检查 SQL 历史**：查看高频、最近、失败和过时查询。
6. **维护业务口径**：查看和编辑已确认的分析口径，并保留来源与更新时间。

### 1.2 Must Have

| 模块 | 内容 | 优先级 |
| --- | --- | --- |
| Dashboard Server | Express HTTP 服务、REST API、静态资源与生命周期管理 | P0 |
| 分析报告中心 | 历史 Session 报告列表、摘要、筛选、完整报告入口 | P0 |
| 数据字典管理 | 表列表、字段列表、含义/状态/备注编辑、批量确认、安全持久化 | P0 |
| 数据预览与列统计 | 前 N 行、类型、空值率、唯一值数或近似值 | P0 |
| 图表画廊 | 跨报告图表缩略图、来源报告与放大查看 | P0 |
| SQL 历史 | 最近/高频/失败/过时查询的展示、排序与筛选 | P0 |
| 口径管理 | 展示并编辑已确认口径，保留来源、状态和更新时间 | P0 |
| 启动与关闭 | `/dashboard`；已有 CLI 基础时增加 `pi-data dashboard` | P0/P1 |
| 安全与并发 | localhost、写令牌、Origin 检查、revision、原子写入 | P0 |
| v0.1～v0.5 回归锁定 | 已有工具、Hook、报告和 TUI 能力不退化 | P0 |

### 1.3 Should Have

- 报告、图表、SQL 和表名搜索；
- 字典按状态筛选；
- 数据字典导出 Markdown；
- 图表按报告、数据集、时间筛选；
- 明暗主题切换，默认 Catppuccin Mocha；
- 记住最近一次打开的 Tab 和数据表；
- 空状态、加载状态、错误状态与保存状态提示。

### 1.4 Deferred to v0.7+

| 功能 | 推迟原因 |
| --- | --- |
| Dashboard 内直接执行任意 SQL | 会改变现有安全模型，需要单独设计权限与资源限制 |
| Agent 实时思考/工具调用流 | 需要 Agent 进程通信或 WebSocket |
| 多用户、账号和远程访问 | 当前定位为本地个人工具 |
| 修改 DuckDB 物理 Schema | v0.6 只维护字典元数据，不修改真实表结构 |
| 多报告结果对比 | 需要统一分析产物模型和差异算法 |
| 插件与主题系统 | 当前阶段属于过度工程化 |

## 2. 核心产品原则

1. **TUI 做分析，Dashboard 做管理**：Dashboard 不替代 Agent 对话，不在本版本内执行任意 SQL。
2. **报告优先，图表不脱离上下文**：图表画廊必须保留来源报告、任务摘要和生成时间。
3. **物理 Schema 只读，字典元数据可编辑**：用户不能通过 Dashboard 新增或删除真实表/字段。
4. **共享数据，不共享业务状态**：Dashboard 与 Agent 共享项目数据目录，但 Dashboard 不维护独立业务数据库。
5. **服务状态临时，用户修改持久**：“关闭即消失”只指 HTTP 服务与内存状态；字典、口径等用户修改必须持久化。
6. **先保证数据可靠，再追求自动保存体验**：任何自动保存不得覆盖其他进程的新修改。
7. **兼容历史报告**：旧报告可通过扫描和解析展示；新报告逐步增加结构化 manifest，减少反向解析 HTML。
8. **无网络依赖**：前端资源本地提供，不依赖 CDN。

## 4. Dashboard Server 与生命周期

### 4.1 配置

```tsx
interface DashboardConfig {
  port?: number;          // 默认 3456
  projectDir: string;     // 当前项目目录
  openBrowser?: boolean;  // 默认 true
  host?: "127.0.0.1";    // 固定值，不接受 0.0.0.0
}

interface DashboardHandle {
  url: string;
  port: number;
  stop(): Promise<void>;
}

function startDashboard(config: DashboardConfig): Promise<DashboardHandle>;
```

### 4.2 启动规则

- 默认绑定 `127.0.0.1:3456`；
- 端口占用时依次尝试 3457～3465；
- 同一项目重复启动时复用已有实例并重新打开浏览器；
- 端口全部占用时返回明确错误，不静默失败；
- TUI 中 `/dashboard` 为 P0；
- `pi-data dashboard` 仅在现有 CLI 已有扩展入口时纳入 P0，否则作为 P1；
- TUI Session 结束时自动停止由该 Session 启动的 Dashboard；
- 独立 CLI 模式通过 `Ctrl+C` 正常关闭；
- 浏览器关闭不等于服务关闭。

### 4.3 基础接口

```
GET /api/health
GET /api/config
```

`/api/config` 只返回前端需要的非敏感配置和当前写令牌，不返回本机绝对路径等敏感信息。

## 5. 通用 API 契约

### 5.1 成功响应

```json
{
  "data": {},
  "meta": {
    "requestId": "req_xxx"
  }
}
```

### 5.2 错误响应

```json
{
  "error": {
    "code": "REVISION_CONFLICT",
    "message": "数据字典已被其他进程更新，请刷新后重试",
    "details": {}
  },
  "meta": {
    "requestId": "req_xxx"
  }
}
```

### 5.3 状态码约定

- `200`：读取或修改成功；
- `201`：创建新的口径元数据成功；
- `400`：参数不合法；
- `403`：写令牌或 Origin 校验失败；
- `404`：表、字段、报告或口径不存在；
- `409`：revision 冲突；
- `413`：请求体或 rows 参数超过上限；
- `422`：数据结构合法但业务状态不允许；
- `500`：内部错误，响应中不得泄露本机路径和堆栈。

## 6. 分析报告中心

### 6.1 定位

“之前做的可视化内容”指完整分析成果，不只指图表图片。报告中心是 Dashboard 默认首页。

### 6.2 页面功能

- 按生成时间倒序展示所有 `session-*.html`；
- 卡片显示：标题、任务摘要、生成时间、涉及数据集、图表数量；
- 支持按关键词、数据集和时间筛选；
- 点击卡片后：
    - 优先在受限 iframe 中打开完整报告；
    - 同时提供“新标签页打开”；
- 报告不存在或损坏时显示错误卡片，不导致整个页面崩溃；
- 没有历史报告时显示明确空状态。

### 6.3 API

```
GET /api/reports?page=1&size=20&query=&dataset=
GET /api/reports/:reportId
GET /api/reports/:reportId/content
```

### 6.4 报告索引策略

采用“新旧兼容”的两阶段方案：

1. **历史报告**：扫描文件名并解析已有 `<meta>`；缺少字段时允许降级。
2. **新报告**：生成报告时同步写入 `reports/manifest.json`，Dashboard 优先读取 manifest。

manifest 最小结构：

```json
{
  "revision": 1,
  "reports": [
    {
      "id": "session-20260716-223000",
      "title": "订单转化率分析",
      "summary": "分析最近 30 天订单转化率变化",
      "createdAt": "2026-07-16T22:30:00+08:00",
      "file": "session-20260716-223000.html",
      "datasets": ["orders", "users"],
      "charts": []
    }
  ]
}
```

不得把报告中的任意脚本直接放到 Dashboard 主页面执行。使用 iframe 时设置 `sandbox`；需要保留报告脚本能力时，只开放最小权限并验证同源影响。

## 7. 数据字典可视化维护

### 7.1 管理边界

- 表名、字段名、字段类型来自真实 DuckDB Schema，只读；
- 用户可编辑：业务含义、确认状态、备注、别名；
- v0.6 不允许新增/删除真实表或字段；
- 如果数据库字段已删除，字典项标记为 `orphaned`，不得静默删除；
- 如果数据库新增字段，字典页显示为待补充状态。

因此，本模块使用“字典维护”，不使用容易误导的“物理 Schema CRUD”。

### 7.2 字段状态

| 状态 | 含义 | 颜色 |
| --- | --- | --- |
| `ai-guessed` | AI 根据字段名或样本推测，尚未由用户确认 | 黄色 `#f9e2af` |
| `user-confirmed` | 用户确认 AI 原始含义正确 | 绿色 `#a6e3a1` |
| `user-corrected` | 用户修改或补充了 AI 含义 | 蓝色 `#89b4fa` |
| `uncertain` | 当前无法可靠判断 | 红色 `#f38ba8` |

### 7.3 状态转换

```
ai-guessed
├── 用户直接确认原含义 → user-confirmed
├── 用户修改含义并保存 → user-corrected
└── 用户标记无法判断 → uncertain

uncertain
├── 用户补充含义并保存 → user-corrected
└── 用户确认现有含义 → user-confirmed

user-confirmed
└── 用户再次修改含义 → user-corrected
```

状态由用户显式选择时遵循用户选择；否则按上述规则自动推导。

### 7.4 页面功能

- 左侧表列表显示字段数、已确认数、不确定数；
- 字段表格显示字段名、类型、状态、业务含义、备注；
- 点击含义或备注进入 inline 编辑；
- 状态通过下拉菜单切换；
- 支持关键词和状态筛选；
- 支持勾选字段并“确认选中字段”；
- “全部确认”需要二次确认，显示影响数量，且默认不包含 `uncertain`；
- 页面显示“保存中 / 已保存 / 保存失败 / 内容有冲突”；
- 提供刷新与导出 Markdown；
- 修改后 Agent 下一轮读取时立即生效。

### 7.5 API

```
GET   /api/dictionaries
GET   /api/dictionaries/:table
PATCH /api/dictionaries/:table/:column
PATCH /api/dictionaries/:table
GET   /api/dictionaries/:table/export?format=markdown
```

单字段更新：

```json
{
  "description": "订单实际支付金额",
  "notes": "含税，扣除退款前",
  "status": "user-corrected",
  "expectedRevision": 12
}
```

批量确认：

```json
{
  "operation": "confirm-selected",
  "columns": ["order_id", "created_at"],
  "expectedRevision": 12
}
```

不使用 PUT 自动覆盖整张表。

### 7.6 持久化可靠性

- 同一进程内，字典写操作必须串行；
- 写入临时文件后先解析校验，再使用 rename 原子替换；
- 每次成功写入递增 revision 并更新 `updatedAt`；
- 客户端携带 `expectedRevision`；版本不一致返回 `409`；
- 写失败时保留旧文件；
- 所有修改写入 `audit.log`，记录时间、操作类型、表、字段和修改前后摘要；
- 不在日志中记录完整敏感样本值。

## 8. 数据预览与列统计

### 8.1 页面功能

- 顶部选择数据集或表；
- 默认展示前 50 行；
- 可选择 10、50、100、200 行，最大 200；
- 宽表支持横向滚动和冻结字段名；
- 列统计显示类型、空值率、唯一值数；
- 明确标注统计口径是全表还是抽样；
- NULL、日期、Decimal、超长文本使用稳定序列化；
- 敏感字段沿用现有 PII 展示策略。

### 8.2 性能边界

- 预览查询只能执行系统生成的只读 SQL；
- 表名必须从 `listTables` 结果中精确匹配，不得直接拼接路由参数；
- 标识符使用 DuckDB adapter 的安全引用函数；
- 列统计默认最多处理 100 列；超过时提示用户选择列；
- 空值率可全表计算；
- 唯一值数优先使用 DuckDB 近似统计或现有统计能力，并在 UI 标记“近似”；
- 单次统计超时建议 5 秒；超时后降级为样本统计，而不是阻塞页面；
- Dashboard 使用只读连接，不允许写入 DuckDB。

### 8.3 API

```
GET /api/datasets
GET /api/datasets/:table/preview?rows=50
GET /api/datasets/:table/schema
GET /api/datasets/:table/stats?mode=auto
```

响应必须返回 `calculationMode: full | approximate | sample`，避免用户误把抽样统计当成全量结果。

## 9. 图表画廊

### 9.1 页面功能

- 跨 Session 展示历史图表缩略图；
- 每张图显示标题、生成时间、来源报告、涉及数据集；
- 支持按报告、数据集、时间筛选；
- 点击后放大，并可跳回完整报告；
- 图表不存在或提取失败时展示占位卡片。

### 9.2 图表索引策略

1. 新报告生成时，优先把图表元数据写入 manifest；
2. 对旧报告，兼容解析 `<img src="data:image/...">`；
3. 服务端不得尝试“解析 HTML 后截图 canvas”；canvas 图表只能在浏览器打开完整报告后渲染；
4. 如果旧报告因体积限制未内联大图，使用原始资源路径；资源也不存在时标记 unavailable；
5. API 默认只返回缩略图或资源 URL，不在列表响应中传输完整大体积 base64。

### 9.3 API

```
GET /api/charts?page=1&size=24&reportId=&dataset=
GET /api/charts/:chartId
```

## 11. 口径管理

### 11.1 定位

口径是跨分析复用的业务定义，例如“GMV 是否含税”“有效订单是否排除退款”。它与字段字典相关，但不等同于单字段说明。

### 11.2 页面功能

- 展示口径名称、定义、适用数据集、来源、状态、更新时间；
- 支持搜索和按数据集筛选；
- 支持编辑已有口径；
- 支持新增用户确认口径；
- 删除操作采用软删除或归档，避免历史报告失去解释依据；
- 修改口径时显示可能受影响的数据集；
- Agent 下一轮启动或读取上下文时使用最新有效口径。

### 11.3 存储决策

开发前先检查 `agent.md` 中现有口径是否已有稳定、可解析的结构：

- 如果已有稳定结构：复用现有 parser 和 writer；
- 如果只是自由文本：不要直接用字符串替换编辑 `agent.md`，新增结构化 `metrics.json`，并由现有上下文加载流程读取；
- 不允许同时维护两份互不一致的口径真源。

推荐模型：

```json
{
  "id": "metric_gmv",
  "name": "GMV",
  "definition": "已支付订单金额，含税，扣除全额退款订单",
  "datasets": ["orders"],
  "status": "user-confirmed",
  "source": "user",
  "revision": 3,
  "updatedAt": "2026-07-17T00:00:00+08:00",
  "archived": false
}
```

### 11.4 API

```
GET    /api/metrics
POST   /api/metrics
PATCH  /api/metrics/:metricId
DELETE /api/metrics/:metricId   # 实际执行软删除/归档
```

口径写入同样使用 revision、原子写入和审计日志。

## 13. 安全要求

1. 服务固定监听 `127.0.0.1`，不得接受 `0.0.0.0`。
2. 启动时生成随机写令牌；所有 POST、PATCH、DELETE 请求必须携带。
3. 写请求检查 `Origin` 和 `Content-Type: application/json`。
4. 限制请求体大小，例如 256KB。
5. 路由中的 table、column、reportId 只能匹配已索引实体，不直接作为路径或 SQL 片段。
6. 文件读写复用 `SecurityChecker.checkPath()`，只允许项目数据目录和报告目录。
7. 数据预览只允许系统生成的 SELECT，不开放任意 SQL 输入。
8. 历史报告使用 sandbox iframe 或新标签页打开，不让报告脚本直接进入 Dashboard 主页面上下文。
9. API 错误不得暴露本机绝对路径、堆栈、令牌或原始敏感数据。
10. 字典和口径修改写入审计日志。

## 17. 发布判定

### 17.1 可发布条件

- 六个页面均具备完整加载、空状态和错误状态；
- 历史报告和图表可追溯到完整分析上下文；
- 字典编辑、状态转换和批量确认可靠；
- 字典与口径修改使用 revision、原子写入和审计日志；
- 数据预览与列统计有明确资源上限和统计口径；
- SQL 历史只读；
- 服务仅监听 localhost，写接口保护生效；
- Dashboard 与 Agent 并行运行时无数据损坏和不可接受的 DuckDB 锁冲突；
- v0.1～v0.5 回归无退化。

### 17.2 不可发布条件

- 字典或口径保存可能覆盖其他进程的新修改；
- 写入中断会破坏 JSON；
- Dashboard 可修改物理 Schema 或执行任意 SQL；
- 报告中的脚本可以控制 Dashboard 主页面；
- API 暴露到非 localhost；
- 图表只展示图片但无法找到来源报告；
- 抽样统计未标注却被展示为全量统计；
- v0.4/v0.5 报告生成、打开或索引流程退化。

## 18. 主要风险与降级策略

### 18.1 DuckDB 文件锁

- Dashboard 只使用只读连接；
- 如果 SDK 的只读并发仍不稳定，优先复用 Agent 已有的只读 adapter；
- 预览失败时显示“数据源当前正被占用”，不得影响字典和报告页面。

### 18.2 历史报告结构不统一

- manifest 为新报告的稳定入口；
- 旧报告解析失败时仍可作为普通文件打开；
- 不因一份损坏报告阻塞整个索引。

### 18.3 agent.md 不适合结构化编辑

- 不对自由文本执行脆弱的字符串替换；
- 改用单一结构化口径存储，并接入现有上下文加载链路；
- 迁移前保留备份和兼容读取。

### 18.4 功能范围较大

- 实施时保持全部模块，但按“先后端可靠性、再基本 UI、最后筛选和视觉细节”的顺序推进；
- 不以省时间为由删除安全、并发和回归测试；
- 某个非核心页面未完成时不得用空壳页面冒充验收通过。
