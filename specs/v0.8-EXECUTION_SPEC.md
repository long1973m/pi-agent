## 2. Bug 修复（P0）

### F-1：analysis 报告生成后 Dashboard 不可见

#### 2.1.1 根因定位

```
TUI generate_analysis_report ──→ 写入 .pi-data-agent/output/???
Dashboard ReportIndexService  ──→ 扫描 reports/ 目录
```

两种可能：
1. 输出路径不一致：analysis 报告写入到了非 Dashboard 扫描路径
2. manifest.json 未同步：即使路径对齐，报告生成后未写入 manifest.json，Dashboard 无法发现

#### 2.1.2 修复方案

**必选**（二选一，优先方案 A）：

**方案 A：统一输出路径到 `reports/`**

- `generate_analysis_report` 默认输出路径改为 `{cwd}/reports/analysis-{timestamp}-{uuid}.html`
- `generate_session_report` 默认输出路径改为 `{cwd}/reports/session-{timestamp}-{uuid}.html`
- 确保 `security.checkPath()` 白名单包含 `reports/` 子目录
- 生成后同步写入 `reports/manifest.json`

**方案 B：Dashboard 扫描路径扩展**

- `ReportIndexService` 同时扫描 `reports/` 和 `.pi-data-agent/output/`
- manifest.json 写入逻辑与 TUI 报告生成解耦

**选择方案 A 的理由**：
- 路径统一，逻辑清晰
- 与 `build-index.ts` 和 `ReportIndexService` 现有设计一致
- 避免跨目录扫描带来的安全边界模糊

#### 2.1.3 manifest.json 同步

`generate_analysis_report` 完成时：

```typescript
// 追加到 manifest.json
const manifest = readManifest();
manifest.reports.push({
  id: reportId,
  title: draft.title,
  summary: draft.executiveSummary.map(s => s.text).join(" ").slice(0, 200),
  type: "analysis",
  sourceSessionId: sessionId,
  createdAt: new Date().toISOString(),
  file: `analysis-${reportId}.html`,
  datasets: evidence.scope,
  evidencePath: evidencePath,   // B3 字段
});
manifest.revision++;
manifest.updatedAt = new Date().toISOString();
atomicWrite("reports/manifest.json", manifest);
```

#### 2.1.4 验收标准

- TUI 中执行 `帮我做一份电商订单分析报告` → HTML 生成成功
- 打开 Dashboard → "分析报告"Tab 中可见新生成的正式报告
- 报告卡片显示正确的标题、生成时间、数据集

### F-2：AI 推断按钮点击无反应

#### 2.2.1 根因定位

三种可能：
1. 前端 `runInference()` 未绑定正确的 API 端点
2. 后端缺少 `POST /api/dictionaries/:table/inference` 路由
3. LLM 调用失败，前端未处理错误

#### 2.2.2 修复方案

**第一步：确认前端按钮绑定**

```javascript
// app.js 中查找 runInference 的实现
async function runInference() {
  const res = await fetch(`/api/dictionaries/${currentTable}/inference`, {
    method: "POST",
    headers: { "Content-Type": "application/json", "X-Write-Token": writeToken }
  });
  if (!res.ok) { showError(await res.text()); return; }
  const result = await res.json();
  renderSuggestions(result.suggestions);
}
```

**第二步：确认后端路由存在**

```typescript
// routes/dictionaries.ts 中添加
router.post("/api/dictionaries/:table/inference", localOnly, originCheck, writeTokenGuard, async (req, res) => {
  const table = validateIdentifier(req.params.table);
  const context = await collectInferenceContext(table);
  const result = await inferDictionary(context);
  res.json({ suggestions: result.suggestions });
});
```

**第三步：错误处理**

- 推断失败返回 500，前端显示"推断失败：{reason}"
- 推断超时（>30s）返回 504，前端显示"推断超时，请重试"
- 无 LLM 配置返回 503，前端显示"未配置 AI 模型，推断功能不可用"

#### 2.2.3 验收标准

- Dashboard 字典页点击"AI 推断"按钮
- 按钮变为 loading 状态
- 完成后字段列表更新，显示置信度标签和建议含义
- 推断失败时有明确错误提示（非空白无反应）

## 3. 报告中心重构（P1）

### A-1："分析报告"Tab 内部分两栏

#### 3.1.1 当前状态

- 顶部有三个分类按钮：全部 / 正式分析报告 / 分析过程记录
- 点击筛选后列表刷新
- 用户反馈：希望在一个页面内自然看到两类报告

#### 3.1.2 目标设计

**Tab 名称**：保持"分析报告"（4 个字）

**页面内部结构**：

```
┌─ 正式分析报告 ──────────────────┐  ← section-header + count badge
│ ┌─────────┐  ┌─────────┐        │  ← 卡片网格（2-3 列）
│ │ [卡片1] │  │ [卡片2] │        │     每卡：标题、摘要、生成时间、
│ │ 覆盖率  │  │ 覆盖率  │        │          数据集标签、三按钮
│ │ 缩略图  │  │ 缩略图  │        │
│ └─────────┘  └─────────┘        │
├─ 分析过程记录 ──────────────────┐  ← section-header + count badge
│ ┌─────────────────────────────┐ │  ← 紧凑列表
│ │ ○ 会话-20260718-1234        │ │     每行：标题、生成时间、数据集、
│ │   电商订单分析 | 2张图表     │ │          图表数、"生成正式报告"按钮
│ │   [生成正式报告]            │ │
│ ├─────────────────────────────┤ │
│ │ ○ 会话-20260717-...         │ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
```

#### 3.1.3 样式差异

| 维度 | 正式分析报告 | 分析过程记录 |
|------|-------------|-------------|
| 卡片大小 | 大卡片（宽 280-320px） | 紧凑行（单行 60px） |
| 信息密度 | 标题 + 摘要 + 覆盖率 + 缩略图 | 标题 + 时间 + 数据集 + 操作 |
| 操作按钮 | 打开 / 打印 / 查看过程 | 生成正式报告 |
| 视觉权重 | 高（阴影/边框突出） | 低（简洁行式） |
| 排序 | 按生成时间倒序 | 按生成时间倒序 |

#### 3.1.4 空状态

- 正式报告为空：显示"暂无正式分析报告。在 TUI 中完成分析后，Agent 会自动生成"
- 过程记录为空：显示"暂无分析过程记录。在 TUI 中执行查询和可视化后，记录将在此显示"

#### 3.1.5 验收标准

- 打开"分析报告"Tab，两栏同时可见
- 正式报告区域显示 analysis 类型卡片（如有）
- 过程记录区域显示 session 类型列表（如有）
- 分类按钮（全部/正式/过程）**移除**，不再需要
- 两栏各自独立滚动

### A-2：图表画廊合并到报告卡片

#### 3.2.1 当前状态

- 独立"图表画廊"Tab，展示跨报告的图表缩略图网格
- 用户反馈：不需要单独看图表，希望和报告一起看

#### 3.2.2 目标设计

**移除"图表画廊"Tab** → 导航变为 5 个 Tab。

**图表嵌入到正式报告卡片**：

```
┌─ 正式分析报告 ──────────────────┐
│ ┌─────────────────────────────┐ │
│ │ 电商订单渠道分析              │ │
│ │ 2026-07-18 14:32 · 2个数据集│ │
│ │                             │ │
│ │ ┌─────┐ ┌─────┐            │ │  ← 图表缩略图（最多 3 张）
│ │ │ 📊  │ │ 📊  │            │ │
│ │ └─────┘ └─────┘            │ │
│ │                             │ │
│ │ 证据覆盖率: 100% ████████   │ │
│ │ [打开] [打印] [查看过程]    │ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
```

**数据来源**：
- 优先从 `manifest.json` 的 `charts` 数组读取
- Fallback：解析报告 HTML 中的 `<img>` 标签提取图表路径

**缩略图展示规则**：
- 每张卡片最多展示 3 张图表缩略图
- 超过 3 张显示"+N"遮罩
- 缩略图点击打开完整报告并定位到图表位置

#### 3.2.3 过程记录中的图表

过程记录行中显示"N 张图表"文字，不展示缩略图（保持紧凑）。

#### 3.2.4 验收标准

- "图表画廊"Tab 从导航中消失
- 正式报告卡片中可见图表缩略图
- 缩略图点击行为正确
- 过程记录行显示图表数量

## 4. SQL 历史编辑（P2）

### A-3：SQL 历史元数据编辑

#### 4.1.1 当前状态

- SQL 历史只读：显示自然语言问题、SQL、执行次数、时间戳、状态
- Spec §10 明确规定"本版本只读"

#### 4.1.2 目标设计

**可编辑字段（限定元数据，不改 SQL 本身）**：

| 字段 | 可编辑 | 说明 |
|------|--------|------|
| 自然语言问题（user_intent） | ✅ | 用户可修正描述 |
| 备注（notes） | ✅ | 新增字段，用户自由填写 |
| 手动状态（status） | ✅ | active / outdated / archived |
| SQL 语句 | ❌ | 不改，避免与报告一致性冲突 |
| 执行次数 | ❌ | 系统统计 |
| 时间戳 | ❌ | 系统记录 |

**编辑入口**：

```
SQL 历史列表中，每条记录右侧增加 [编辑] 按钮
点击后弹出行内编辑面板：
┌─ 编辑 SQL 记录 ─────────────┐
│ 自然语言问题：_____________ │
│ 备注：____________________ │
│ 状态：[active ▼]           │
│                             │
│ [保存] [取消]               │
└─────────────────────────────┘
```

#### 4.1.3 持久化

- 使用 `AtomicStore` 管理 `query-memory.json` 的写入
- 编辑时携带 `expectedRevision`，冲突时 409
- 编辑后 `updatedAt` 更新

#### 4.1.4 后端 API

```
PATCH /api/sql-history/:entryId
Body: { userIntent?: string, notes?: string, status?: "active"|"outdated"|"archived", expectedRevision: number }
```

#### 4.1.5 安全

- write-token 校验（已有）
- entryId 格式校验（`/^[\w-]+$/`）
- status 只允许三个枚举值

#### 4.1.6 验收标准

- SQL 历史列表有"编辑"按钮
- 点击后弹出编辑面板
- 修改 user_intent / notes / status 后保存成功
- 刷新页面后修改仍然存在
- 状态筛选（active/outdated/failed/archived）包含 archived
