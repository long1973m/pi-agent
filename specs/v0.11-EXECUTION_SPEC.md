## 3. S-1：确认门 fail-closed——无 UI 环境写操作静默放行（P0，最高优先 Bug）

### 3.1 根因

确认分支的条件写成了 `if (sqlCheck.action === "confirm" && ctx.ui)`（`src/tools/query-data.ts:73`）：headless / 无 UI 模式下 `ctx.ui` 不存在，整个确认分支被整体跳过，SQL **照样执行**。这是 fail-open 语义——保护机制在最需要它的环境里失效。同样模式共三处：

```
src/tools/query-data.ts:73
src/tools/load-data.ts:442
src/tools/export-result.ts:122
```

### 3.2 方案要点

confirm 分支语义改为显式三态，杜绝隐式放行：

```
autoConfirmWrite === true  → 放行，并在结果 details 中标记 auto-confirmed
ctx.ui 存在                → 弹确认（现状行为保留）
两者皆无                   → block，返回错误信息：
  "该操作需要用户确认，请交互模式运行，或显式配置 PI_DATA_AGENT_AUTO_CONFIRM_WRITE=true"
```

三处调用点统一走同一套判定逻辑，不留第四种分支组合。

### 3.3 验收标准

- [ ] 无头环境下执行 UPDATE / CREATE TABLE 等 SQL 返回 blocked，错误信息含上述指引文案
- [ ] `autoConfirmWrite = true` 时放行，且结果 details 有 auto-confirm 标记
- [ ] 交互模式下确认弹窗行为不变
- [ ] 现有 vitest 全绿

## 4. S-2：SQL 执行引擎级收口——路径白名单与读写分类可被绕过（P0，安全）

### 4.1 根因

**根因 1（文件读取绕过）**：`src/engine/duckdb.ts:92` 的 `DuckDBInstance.create` 未做任何外部访问限制；query_data 只做关键词分类（`security.checkSql`），路径白名单只在工具参数层生效（如 load-data.ts:435）。因此模型可在 query_data 里直接执行：

```sql
SELECT * FROM read_csv('/Users/other/secret.csv')   -- 读任意本机文件
SELECT * FROM read_text('/etc/passwd')              -- 同上
SELECT * FROM parquet_scan('/anywhere/data.parquet')
COPY (SELECT ...) TO '/any/path/out.csv'            -- 经一次 confirm 写任意路径
```

**根因 2（CTE 夹带写）**：`src/security.ts:181` 的 `/^\s*WITH\s+.*\s+SELECT\s+/s` 把 WITH...SELECT 整体归类为 read 直接放行，但 DuckDB 支持在 CTE 里夹带写操作：

```sql
WITH x AS (DELETE FROM t RETURNING *) SELECT * FROM x   -- 分类为 read，实际带写
```

### 4.2 方案要点（分两层：a 必做、b 必做、c 可选 stretch）

**a. 文件访问白名单（必做）**
先核验 @duckdb/node-api 1.5.x 是否支持 `SET allowed_paths` / `allowed_directories`（DuckDB 1.1+ 特性）：

- 支持 → 引擎级收口：把文件系统访问限定到 `config.allowedPaths`
- 不支持 → SecurityChecker 新增 table function 参数校验：从 SQL 中提取 `read_csv` / `read_csv_auto` / `read_parquet` / `read_json*` / `read_text` / `glob` / `sniff_csv` / `parquet_scan` 以及 `COPY ... TO` 引号内路径，逐个过 `checkPath`

**b. classifySql 修补（必做）**
- 清理注释后先剥离字符串字面量（避免 `'DROP TABLE x'` 这类字面量误报）
- 然后在**全文任意位置**检测写关键词（INSERT / UPDATE / DELETE / CREATE / DROP / ALTER / COPY / TRUNCATE / MERGE），命中则至少归类 write（走确认门）——不再只看语句开头
- 与 dangerousPatterns 的优先级保持：DROP / TRUNCATE / GRANT / REVOKE / EXECUTE 仍为 dangerous

**c. 事务回滚沙箱（可选 stretch）**
query_data 走事务回滚沙箱（`BEGIN; ...; ROLLBACK`）或独立只读连接，从机制上保证只读，而不只靠分类。

### 4.3 风险警示（实施前必读）

- **不能**简单 `SET enable_external_access=false` 一刀切——load_data 自身依赖 `read_csv_auto`（load-data.ts:106-114），connect_database 依赖 ATTACH，一刀切会直接破坏核心功能
- 收紧 classifySql 必然带来误报风险，验收必须包含字面量误报样本（见 4.4）

### 4.4 验收标准

- [ ] 越界绝对路径的 read_csv 被 block（路径不在 config.allowedPaths 内）
- [ ] `WITH x AS (DELETE FROM t RETURNING *) SELECT * FROM x` 被拦截或要求确认
- [ ] `WHERE name = 'DROP TABLE x'` 这类字面量不再触发 dangerous 误判（或明确记录为接受的保守误报并写入代码注释）
- [ ] load_data / query_data / export_result 全功能回归通过（vitest 98 用例 + acceptance 脚本）

## 5. S-3：Dashboard DNS rebinding 防护——GET 接口无 Origin 校验（P0，安全）

### 5.1 根因

`src/dashboard/middleware/origin-check.ts` 只对写请求校验 Origin；`local-only.ts` 只看 socket.remoteAddress。DNS rebinding 场景下：恶意网页把域名解析到 127.0.0.1 → remoteAddress 合法、Origin 为攻击者域名，但 GET 请求不做校验 → 可读取 reports 内容、datasets preview 等明文数据。

### 5.2 方案要点

- 新增 host-check 中间件，挂载顺序在 localOnly 之后、路由之前
- 校验 Host 头必须为 `127.0.0.1:{port}` 或 `localhost:{port}`，否则返回 403
- port 不硬编码，从启动 handle 动态获取（配合现有动态端口机制）

### 5.3 验收标准

- [ ] `curl -H "Host: evil.com" http://127.0.0.1:{port}/api/reports` 返回 403
- [ ] 正常浏览器访问（127.0.0.1 / localhost）不受影响
- [ ] 补充中间件单测（合法 Host 放行 / 非法 Host 403）

- nav-context.ts:145/176：导航预算截断会截掉 pinned 段尾部，而非按优先级裁剪（工作量大可记入 BACKLOG）

## 13. 风险与注意事项

| 风险 | 说明 | 对策 |
|------|------|------|
| `enable_external_access=false` 一刀切 | 会破坏 load_data 自身的 `read_csv_auto`（load-data.ts:106-114）与 connect_database 的 ATTACH | 禁止一刀切；按 S-2 方案 a 的两条路径二选一，白名单粒度收紧 |
| classifySql 收紧的误报 | 字符串字面量中的关键词、非常规 SQL 可能被误判 dangerous/write | 剥离字面量后再匹配；验收必含 `'DROP TABLE x'` 字面量样本；误报须回归 98 用例 + acceptance 脚本 |
| git init 顺序错误 | 先 add 后写 .gitignore 会把 node_modules、session.duckdb、token 等永久写入历史 | **必须先写 .gitignore，再首次 add**；首提前 `git status` 逐项核对 + du 复核体积 |
| 测试迁移期间双轨混乱 | 迁移一半时新旧运行器都跑不全，出现"以为绿了其实没跑" | 迁移期间保持 `test:all` 双轨直到迁移完成，再退役 legacy（或降为冒烟）；迁移期间每次提交两轨都要绿 |
| S-1 fail-closed 影响存量自动化 | 依赖静默放行的 headless 流程升级后会开始 blocked | 属预期行为；引导其显式配置 `PI_DATA_AGENT_AUTO_CONFIRM_WRITE=true` |
| host-check 过严锁死自身 | 用户通过非 localhost 别名访问 Dashboard 被拒 | 只放行 127.0.0.1 / localhost 两种 Host 是设计内行为；错误页面给出指引 |
