## 2. 核心设计原则

### 2.1 v0.3 不再以"工具数量"为核心指标

v0.3 的判断标准不是新增多少工具，而是：

```
面对真实业务数据，Agent 是否能：
1. 正确理解字段
2. 主动澄清口径
3. 生成可信 SQL
4. 给出合理分析
5. 选择合适图表
6. 输出可复查报告
```

---

### 2.2 每个分析结论必须可追溯

所有分析输出必须包含：

```
SQL
数据范围
字段口径
是否使用 ai-guessed 字典
是否使用采样
图表路径
不确定性说明
```

---

### 2.3 不破坏既有主流程

v0.3 所有改动不得破坏：

```
load_data → describe_data → query_data → visualize → export_result
```

每完成一个模块，必须跑 v0.1 / v0.2 回归测试。

---

### 2.4 真实数据优先于 toy data

v0.3 继续保留 iris 测试，但不能只依赖 iris。必须加入更接近业务的数据：

```
订单数据

保险保单 / 理赔模拟数据
```

### 3.1 数据字典用户确认 / 修正

#### 文件

```
src/hooks/data-dictionary.ts
src/tools/describe-data.ts
src/tools/ask-clarification.ts
src/persistence.ts
src/types.ts
```

#### 目标

将 v0.2 的 `ai-guessed` 数据字典升级为可确认、可修正、可复用的数据字典。

#### 当前问题

v0.2 已能自动生成字段语义，但状态多为：

```
ai-guessed
```

真实业务数据中，字段名可能很隐晦：

```
amt
prem
chnl
stat
is_act
claim_cnt
```

如果不确认，后续分析容易建立在错误字段理解上。

#### 实现要求

1. `describe_data` 展示数据字典时，必须标注状态：
    - `ai-guessed`
    - `user-confirmed`
    - `user-corrected`
2. 用户可以对字段语义做三类操作：
    - 确认全部字段
    - 修改单个字段含义
    - 标记字段为"不确定"
3. 确认后持久化保存：

```tsx
{
  tableName: string;
  columns: Array<{
    name: string;
    type: string;
    inferredMeaning: string;
    userMeaning?: string;
    status: "ai-guessed" | "user-confirmed" | "user-corrected" | "uncertain";
    confirmedAt?: string;
  }>;
}
```

1. `query_data` 使用字段时：
    - 优先使用 `userMeaning`
    - 其次使用 `inferredMeaning`
    - 如果字段状态为 `uncertain`，必须提示不确定性
2. 字典确认失败不得阻塞查询，但必须 warning。

#### 验收标准

| 项 | 标准 |
| --- | --- |
| 展示状态 | describe_data 能显示字段字典状态 |
| 用户确认 | 可将 ai-guessed 改为 user-confirmed |
| 用户修正 | 可修改字段含义并保存 |
| 查询复用 | query_data 能使用已确认字段含义 |
| 不确定提示 | uncertain 字段使用时会提示 |
| 持久化 | 重启后字典状态不丢失 |

### 3.2 statistical-analysis Skill 初版

#### 目录

```
├── SKILL.md
└── scripts/

    ├── correlation.sql

```

#### 目标

让 Agent 具备基础统计分析能力，但不做复杂统计建模。

#### v0.3 范围

只做四类：

```
1. 分组描述统计
2. 相关性分析
3. 异常值检测
4. 简单趋势分析
```

#### 不做

```
复杂回归
因果推断
假设检验大全
预测模型
机器学习训练
```

#### SKILL.md 必须包含

1. 适用场景
2. 不适用场景
3. 统计方法选择规则
4. 主动反问模板
5. 不确定性说明模板
6. 示例分析流程
7. SQL 模板引用

#### 方法选择规则

```
用户问"整体情况" → 分组描述统计
用户问"有没有关系" → 相关性分析
用户问"异常 / 离群 / 反常" → 异常值检测
用户问"趋势 / 变化 / 增长" → 简单趋势分析
```

#### SQL 模板说明

趋势分析使用 `trend-analysis.sql`：

```sql
-- 按时间字段聚合，计算环比变化率
SELECT
  DATE_TRUNC('month', time_column) AS period,
  SUM(metric) AS total,
  LAG(SUM(metric)) OVER (ORDER BY DATE_TRUNC('month', time_column)) AS prev,
  (SUM(metric) - LAG(SUM(metric)) OVER (ORDER BY DATE_TRUNC('month', time_column)))
    / NULLIF(LAG(SUM(metric)) OVER (ORDER BY DATE_TRUNC('month', time_column)), 0) AS change_rate
FROM table
GROUP BY 1
ORDER BY 1;
```

趋势判断逻辑（Agent 根据结果判断）：
- 连续 3 期 change_rate > 0 → "上升趋势"
- 连续 3 期 change_rate < 0 → "下降趋势"
- 正负交替 → "波动趋势"
- 绝对值 < 5% → "基本平稳"

#### 主动反问模板

当用户说：

```
分析一下数据
看看有没有问题
做个统计分析
```

但未指定目标时，必须反问：

```
你想优先看哪类统计分析？

1. 整体分布：均值、中位数、分位数、缺失率
2. 分组对比：按类别字段比较关键指标
3. 异常检测：查找极端值、异常波动、缺失异常
4. 相关性：查看数值字段之间是否相关
```

每个选项必须带 `impliedAssumption`。

#### 验收标准

| 项 | 标准 |
| --- | --- |
| 分组描述统计 | 能按类别字段输出 count / mean / median / min / max |
| 相关性分析 | 能输出数值字段相关系数矩阵 |
| 异常检测 | 能用 IQR 或 Z-score 找出异常值 |
| 趋势分析 | 能按时间字段聚合并判断上升 / 下降 / 波动 |
| 反问 | 模糊统计请求触发结构化反问 |
| 不确定性 | 不把相关性说成因果关系 |
