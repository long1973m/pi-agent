# Pi Data Agent v0.9 执行 Spec｜个人用户体验专项：数据入口 + 首次引导 + 主动体检

<aside>
🔧

版本定位：v0.9 = 可用性/体验专项版本。打通个人用户最常见的数据入口（Excel、网页上传自动加载），补齐首次运行引导与环境自检，让 Agent 在加载数据后主动开口（数据体检卡 + 建议问题），并消除 TUI 调试日志噪音。

</aside>

> **核心目标**：把"给懂 SQL 的开发者用的分析工具"向"个人数据助理"推进一公里——降低数据进入门槛、消除首次使用的隐性依赖和日志噪音、把被动等提问变成主动给洞察。
>
> **范围决策**：不改动查询引擎核心、不改动报告管线与质量门槛、不改动安全模型。仅扩展 load_data 格式支持、Dashboard 上传链路、session_start 引导、日志分级、加载后画像。

## 2. A-1：load_data 支持 Excel（P0）

### 2.1 方案选型

**必选：Node 侧解析（SheetJS `xlsx` npm 包，Apache-2.0）**。

- 读取文件 Buffer → `XLSX.read(buffer, { type: "buffer" })` → 目标 sheet 转 CSV 文本 → 写临时 CSV → 复用现有 CSV 加载路径（`read_csv_auto`）→ 删除临时文件。
- 类型推断交给 DuckDB `read_csv_auto`，与 CSV 行为完全一致。

**否决方案**：
- DuckDB excel 扩展（`read_xlsx`）：运行时需联网下载扩展二进制，离线环境直接失败，不符合"降低门槛"目标。
- Python openpyxl/pandas：给核心加载路径增加 Python 硬依赖，与 A-3 的"Python 仅影响绘图"定位冲突。

### 2.2 实现要点

- 新增依赖：`xlsx`（锁定最新稳定版）。若安装失败，降级方案为 `exceljs`（接口不同，仅转换层替换）。
- `load_data` 参数新增：`sheet_name?: string`（省略时取第一个 sheet）；返回 details 中附 `availableSheets: string[]`，方便用户换 sheet 重载。
- 扩展名白名单追加 `.xlsx` / `.xls`；格式识别以扩展名优先，magic bytes（`PK\x03\x04`）兜底。
- 表名推导复用现有规则（与 CSV 一致）。
- 防护：单文件解析上限（cell 数 > 5×10⁶ 或解压后 > 200MB 时报错拒绝，防 zip bomb）；解析包在 try/catch 内，失败信息给出人话提示（"文件可能不是有效的 Excel 文件"）。
- 安全检查路径不变：仍走 `security.checkOperation()` 的路径白名单。

### 2.3 验收标准

- [ ] 自然语言「加载 sample.xlsx」成功建表，`describe_data` 可见列与统计
- [ ] 多 sheet 文件：默认加载第一个 sheet，details 列出全部 sheet 名；指定 `sheet_name` 可加载对应 sheet
- [ ] 中文表头、日期、数值列类型正确（日期为 DATE/TIMESTAMP，数值为数值型）
- [ ] 非 Excel 内容伪装 .xlsx 时报错清晰，不崩溃
- [ ] 现有 CSV/TSV/Parquet/JSON 加载行为不变（回归通过）

## 3. A-2：Dashboard 上传后自动加载（P0）

### 3.1 当前状态

`POST /api/upload` 只落盘到 uploads 目录即返回 `{ path, size, originalName, uploadedAt }`。用户必须切回终端对 Agent 说"帮我加载"，工作流断链。

### 3.2 目标设计

```
浏览器上传 ──→ 落盘 uploads/ ──→ 自动调用加载函数建表 ──→ 返回 { ..., loaded }
                                                          ├── ok: true  → tableName/rowCount/columnCount
                                                          └── ok: false → reason（人话）
```

- 从 `UploadDeps` 接收 engine（`index.ts` 已传入 `createDashboardServer`，确认透传到 upload 路由）。
- 将 load_data 内部的"文件→建表"逻辑抽取为可复用函数（建议放 `src/tools/load-data.ts` 导出，或 `src/engine/` 下），工具与上传路由共用，避免两套实现漂移。自动加载同样触发静默字典生成。
- 表名从原始文件名推导（sanitize 规则与 load_data 一致）；同名表覆盖（`CREATE OR REPLACE`），响应中带 `replaced: true` 标记。
- **上限保护**：文件 > 100MB 跳过自动加载，`loaded.ok=false, reason="文件较大，请在 Agent 中手动加载"`——避免阻塞 Dashboard 请求（engine 为串行队列）。
- 加载失败不影响上传本身：HTTP 仍 200，`loaded` 字段如实反映失败原因。
- 前端 `static/app.js`：上传成功 toast 展示"已加载为表 `xxx`（N 行 M 列），可直接在 Agent 中提问"；自动加载失败时展示原因但不阻断。

### 3.3 验收标准

- [ ] Dashboard 拖入 CSV → 响应含 `loaded.tableName` 与行列数 → Agent 侧 `list_datasets` 立即可见该表
- [ ] 上传 xlsx 同样自动加载（依赖 A-1）
- [ ] 故意上传坏文件：上传成功、`loaded.ok=false` 且 reason 可读
- [ ] >100MB 文件跳过自动加载并给出指引
- [ ] 上传 API 现有安全约束（50MB 上限、白名单、UUID 文件名）不变

## 4. A-4：日志分级（P1，先于 A-3 实施）

### 4.1 当前状态

`src/index.ts` 有约 29 处 `console.log/error`（`[PiDataAgent] Event: session_start...` 等）直接打进 TUI，对最终用户是纯噪音。

### 4.2 目标设计

- 新增 `src/utils/logger.ts`：

```typescript
// debug() 仅在 PI_DATA_AGENT_DEBUG=1 或 config.debug=true 时输出到 stderr
// info()/warn()/error() 始终输出；统一前缀 [pi-data-agent]
export function createLogger(scope: string): { debug, info, warn, error }
```

- `config.ts` 新增 `debug?: boolean`（env `PI_DATA_AGENT_DEBUG`，默认 false）。
- `index.ts` 全部 `console.log` 改为 `logger.debug`；真正的初始化失败保留 `logger.error/warn`。
- 其他模块（engine/dashboard lifecycle）中明显的进度类 console.log 一并降级为 debug；错误日志不动。
- 会话时长统计等 shutdown 信息归入 debug。

### 4.3 验收标准

- [ ] 默认启动：TUI 中除欢迎引导（A-3）外无 `[PiDataAgent]` 噪音
- [ ] `PI_DATA_AGENT_DEBUG=1` 时调试日志完整恢复
- [ ] DuckDB 连接失败等真实错误仍然可见

## 5. A-3：环境自检 + 欢迎引导（P1）

### 5.1 当前状态

Python/matplotlib 是 `visualize` 的硬依赖，用户第一次画图失败才发现；新用户不知道能说什么、有哪些命令。

### 5.2 目标设计

**session_start 时异步执行一次自检（不阻塞启动）**，汇总为一段简洁的就绪信息：

```
[pi-data-agent] 就绪 ✓ DuckDB(3 张表) ✓ LLM ✓ Python 绘图 ✗
  绘图不可用：pip install -r requirements.txt 后 visualize 即可使用
试试：「加载 data.csv 看看有什么」·「按渠道统计销售额并画图」·「导出查询结果」
命令：/dashboard 打开控制台 · /report executive|detailed 生成正式报告
```

- 自检项：DuckDB（已有成败结果）、LLM 配置（`resolveLLMConfig` 已有结果）、Python 绘图可用性（复用 `check_python_env.py` 或 `PythonStatelessEngine.checkAvailability()`，结果缓存在 runtime）。
- 输出通道：优先 `ctx.ui?.notify(..., "info")`，不可用时回退单条 `logger.info`。仅在 session_start 输出一次，每轮对话不重复。
- 自检结果存入 runtime：`visualize` 工具失败路径检测到"Python 不可用"时，错误信息直接附带安装命令，而不是裸报错。

### 5.3 验收标准

- [ ] 全部就绪时输出一段 ≤4 行的就绪+引导信息
- [ ] 缺 Python 依赖时明确指出影响范围（仅绘图）与修复命令
- [ ] 未配置 LLM 时提示哪些功能受限（AI 字典推断、正式报告起草）
- [ ] Python 不可用时调 `visualize`，错误信息包含 `pip install -r requirements.txt`
- [ ] 自检不阻塞 session_start（慢速探测异步进行）

## 6. A-5：加载后数据体检卡 + 建议问题（P1）

### 6.1 当前状态

`load_data` 成功后只静默生成字典；system prompt 里仅有"N 行 M 列"。用户要自己想起来说"看看数据"。`data-cleaning` skill 已写好检查逻辑但未接入运行时。

### 6.2 目标设计

新增 `src/hooks/data-profile.ts`：`profileTable(engine, tableName)` 返回结构化画像，**基于一条 `SUMMARIZE <table>` + 少量补充查询**：

| 检查项 | 数据来源 | 呈现 |
|--------|---------|------|
| 行数/列数 | getTableOverview | 基础信息 |
| 缺失率 | SUMMARIZE.null_percentage | >30% 列出"需关注"，>80% 标"严重" |
| 低基数列（疑似分类维度） | SUMMARIZE.approx_unique ∈ [2,20] | 记为候选维度 |
| 时间列 | column_type ∈ DATE/TIMESTAMP + min/max | 给出时间跨度 |
| 主键重复嫌疑 | 名称匹配 `/^id$|_id$/i` 的列做 COUNT−COUNT(DISTINCT) | >0 则警告 |
| 恒定列 | approx_unique = 1 | 提示无区分度 |

**建议问题（规则生成，最多 3 条）**：有时间列→趋势问句；有低基数分类列+数值列→分布/Top N 问句；有金额类数值列→排名问句。

**接入点**：`load_data` execute 成功后调用（best-effort，任何一步失败静默跳过，不影响加载主流程）：

- content 文本追加紧凑体检卡（人话，≤8 行）；
- details 附结构化 `dataProfile` 供模型转述与后续使用。

**防护**：估算行数 > 100 万时只做 SUMMARIZE（跳过逐列补充查询）；整体 try/catch + 单步容错。

### 6.3 验收标准

- [ ] 「加载 ecommerce_orders.csv」后，回复中直接出现体检卡（缺失率/疑似主键/时间跨度）与 3 个建议问题
- [ ] 对体检卡中的问题继续追问，Agent 能直接用 query_data 回答
- [ ] 大表（>100 万行估算）不执行逐列补充查询，体检卡降级为基础信息
- [ ] profile 任一步骤抛错不影响加载结果
- [ ] 现有字典静默生成行为不变

## 8. 风险与降级

| 风险 | 概率 | 影响 | 降级方案 |
|------|------|------|----------|
| `xlsx` 包安装受限（网络/registry） | 低 | 高 | 换 `exceljs`；仍不行则 A-1 延后，其余任务不受阻 |
| SheetJS 解析恶意文件（zip bomb/原型污染） | 低 | 中 | cell 数/体积上限 + 锁定最新版本 |
| 自动加载大文件阻塞 Dashboard 响应 | 中 | 中 | 100MB 上限跳过 + 串行队列天然限流 |
| SUMMARIZE 在超大表上慢 | 中 | 低 | 100 万行降级策略 + best-effort 容错 |
| `ctx.ui.notify` 在部分宿主不可用 | 低 | 低 | 回退 logger.info 单条输出 |
| 日志改造漏改导致仍有噪音 | 中 | 低 | grep 全量扫一遍 `console.log` 收尾 |
