# Pi Data Agent v0.2 执行 Spec｜修订版

> 版本定位：**v0.2 = 可视化闭环 + 口径记忆 + 查询记忆增强 + 可选扩展冲刺**
> 

> 原则：**目标激进，执行分层，验收严格。**

## 0. 前置状态

v0.1 已完成并通过基础人工验收，且以下两个问题已修复：

1. **模糊问题主动反问未触发**
    - `query_data` 已支持 `user_intent`
    - `active-questioning` 已优先基于用户原始问题判断
    - "分析一下这些数据"等开放式请求可触发主动反问
2. **首次查询被数据字典硬拦截**
    - `load_data` 后可自动生成 `ai-guessed` 数据字典
    - `query_data` 不再因缺少数据字典直接 block
    - `ai-guessed` 状态下允许执行，但必须提示字段理解尚未确认

v0.2 不重复修 v0.1 基础闭环，只在其上增强。

## 2. 核心设计原则

### 2.1 不破坏 v0.1 主流程

v0.2 所有改动不得破坏以下主流程：

```
load_data → describe_data → query_data → export_result
```

每次新增功能后都必须跑 v0.1 回归测试。

### 2.2 每个新功能必须有 fallback

| 功能 | fallback |
| --- | --- |
| `visualize` 失败 | 返回临时 CSV 路径 + 错误原因 |
| `show_image` 不支持 TUI 图片 | 返回 PNG 文件路径，提示用户手动打开 |
| `agent.md` 写入失败 | 不阻塞查询，只 warning |
| 过时闸判断失败 | 不召回该条记忆，提示 memory check skipped |
| 失败查询入库失败 | 不影响 query_data 主结果 |
| SQLite connect 失败 | 不影响本地 CSV 主流程 |

### 2.3 分阶段合并

禁止一次性大改所有模块。

执行顺序：

```
阶段 1：可视化闭环
阶段 2：口径记忆
阶段 3：查询记忆增强
阶段 4：Eval 扩展
阶段 5：Stretch Goal 冲刺
```

每阶段必须：

```
实现 → 单测 → 集成测试 → 审查报告 → 再进入下一阶段
```

## 3. Must Have 模块 Spec

### 3.1 visualize 工具

#### 文件

```
src/tools/visualize.ts
src/engine/python-stateless.ts
scripts/generate_chart.py
```

#### 工具目标

将 SQL 查询结果生成 PNG 图表。

#### 输入参数

```tsx
{
  sql: string;
  chart_type: "histogram" | "bar" | "line" | "scatter" | "pie" | "box" | "heatmap";
  x_column: string;
  y_column?: string;
  title?: string;
  output_path?: string;
  user_intent?: string;
}
```

#### 实现要求

1. 只允许 `SELECT` 查询。
2. 先走安全层检查。
3. DuckDB 查询结果写入临时 CSV。
4. 使用 `python-stateless.ts` 调用 `scripts/generate_chart.py`。
5. 生成 PNG 文件。
6. 返回：
    - 图表路径
    - 图表类型
    - 使用字段
    - 数据行数
    - 文件大小
7. 临时 CSV 可保留或清理，但要记录路径。
8. 失败时返回错误原因和临时数据路径，不得影响主流程。

#### Python 要求

`generate_chart.py` 使用：

```
pandas
matplotlib
seaborn
```

必须使用无 GUI 后端：

```python
matplotlib.use("Agg")
```

#### 验收标准

| 项 | 标准 |
| --- | --- |
| bar | 可生成柱状图 |
| line | 可生成折线图 |
| scatter | 可生成散点图 |
| histogram | 可生成直方图 |
| 文件 | PNG 文件真实存在且大小 > 0 |
| 安全 | 非 SELECT SQL 被拒绝 |
| fallback | Python 报错时返回清晰错误 |

### 3.2 show_image 工具

#### 文件

```
src/tools/show-image.ts
```

#### 工具目标

在 TUI 中展示图片；如果不支持，则返回图片路径。

#### 输入参数

```tsx
{
  image_path: string;
  caption?: string;
}
```

#### 实现要求

1. 检查路径是否在白名单内。
2. 检查文件是否存在。
3. 检查文件类型是否为 PNG / JPG / SVG。
4. 若 Pi TUI 支持 image content：
    - 返回 image content。
5. 若不支持：
    - 返回文本提示：
        
        ```
        图表已生成：/path/to/chart.png
        当前 TUI 不支持内嵌图片，请手动打开该文件。
        ```
        

#### 验收标准

| 项 | 标准 |
| --- | --- |
| 安全路径 | 越界路径被拦截 |
| 文件存在 | 不存在时返回明确错误 |
| 图片格式 | 非图片文件被拒绝 |
| fallback | TUI 不支持图片时仍可返回路径 |

### 3.3 visualization Skill

#### 目录

```
skills/visualization/
├── SKILL.md
└── scripts/
    └── chart-templates.sql
```

#### Skill 目标

指导 Agent 正确选择图表，而不是随便画图。

#### SKILL.md 必须包含

1. 适用场景
2. 图表选择规则
3. 字段选择规则
4. 主动反问模板
5. 示例对话
6. 常见失败场景

#### 图表选择规则

```
单数值字段 → histogram / box
类别 + 数值 → bar
时间 + 数值 → line
两个数值字段 → scatter
类别占比 → pie
多个数值字段相关性 → heatmap
```

#### 主动反问模板

当用户说：

```
画个图
可视化一下
展示趋势
```

但未指定图表类型或字段时，必须反问：

```
你想看哪类图？

1. 分布：看某个字段的分布
2. 对比：按类别比较数值
3. 趋势：按时间查看变化
4. 关系：看两个数值字段关系
```

每个选项必须带 `impliedAssumption`。

### 3.4 agent.md 口径回写最小版

#### 文件

```
config/agent.md
src/tools/ask-clarification.ts
src/persistence.ts
src/index.ts
```

#### 目标

用户确认过的口径，下次不重复问。

#### 实现要求

当 `ask_clarification` 成功获得用户选择后，将口径写入：

```
config/agent.md
```

格式：

```markdown
## 活跃用户

- 定义：最近 7 天有登录行为的用户
- 来源问题：分析活跃用户
- 确认时间：2026-06-28Txx:xx:xx
- 状态：user-confirmed
```

#### system prompt 注入

每次 `before_agent_start` 时读取 `config/agent.md`，注入 system prompt：

```
以下是用户已确认的稳定口径，后续分析应优先复用，不要重复询问。
```

#### 注意

先做简单版，不要求复杂术语抽取。  

如果无法自动抽取 term，可用 question 作为标题。

#### 验收标准

| 项 | 标准 |
| --- | --- |
| 写入 | 用户选择后 agent.md 新增口径 |
| 注入 | 下次启动可读取 agent.md |
| 收敛 | 同一问题不重复触发反问 |
| fallback | 写入失败只 warning，不阻塞 |

### 3.5 查询记忆：过时闸最小版

#### 文件

```
src/hooks/query-memory.ts
src/utils/schema-fingerprint.ts
```

#### 目标

表结构变化后，不再召回旧查询。

#### 实现要求

每条查询记忆增加字段：

```tsx
{
  schemaFingerprint: string;
  status: "active" | "outdated" | "failed";
  outdatedReason?: "schema_changed" | "table_missing";
}
```

#### 触发时机

在以下时机检查：

```
before_agent_start
recallRelevantQueries
load_data 覆盖同名表后
```

#### 判断逻辑

1. 从历史 SQL 提取表名。
2. 获取当前 schema fingerprint。
3. 如果与记忆中的 schema fingerprint 不一致：
    - 标记为 `outdated`
    - 不再注入 prompt

#### 验收标准

| 项 | 标准 |
| --- | --- |
| schema 未变 | 记忆可召回 |
| schema 改变 | 记忆标记 outdated |
| table 删除 | 记忆标记 table_missing |
| prompt 注入 | outdated 记忆不注入 |

### 3.6 查询记忆：失败查询入库最小版

#### 文件

```
src/hooks/query-memory.ts
src/tools/query-data.ts
src/error-recovery.ts
```

#### 目标

最终失败的查询要记录，便于后续避免重复错误。

#### 新增字段

```tsx
{
  status: "failed";
  errorMessage: string;
  failureCategory: "syntax_error" | "permission" | "not_found" | "timeout" | "unknown";
}
```

#### 错误分类规则

```tsx
syntax / parse / unexpected → syntax_error
permission / denied / unauthorized → permission
not found / does not exist / no such table → not_found
timeout / timed out / cancel → timeout
其他 → unknown
```

#### 限制

失败查询最多保留 10 条。  

失败查询不参与成功查询容量闸。

#### 验收标准

| 项 | 标准 |
| --- | --- |
| SQL 语法错误 | 入库为 syntax_error |
| 表不存在 | 入库为 not_found |
| 权限问题 | 入库为 permission |
| 最多数量 | 超过 10 条删除最旧失败记录 |
| prompt 注入 | failed 查询不作为成功样例注入 |

### 4.1 connect_database：仅 SQLite

#### 文件

```
src/tools/connect-database.ts
```

#### 范围限制

v0.2 只支持：

```
SQLite
```

不支持：

```
PostgreSQL
MySQL
远程连接
用户名密码连接串
```

#### 输入参数

```tsx
{
  db_type: "sqlite";
  file_path: string;
  alias?: string;
}
```

#### 实现要求

1. 检查 SQLite 文件路径。
2. 必须在白名单内。
3. DuckDB 执行：
    
    ```sql
    ATTACH 'path/to/db.sqlite' AS alias
    ```
    
4. 返回 schema / tables。

#### 验收标准

| 项 | 标准 |
| --- | --- |
| SQLite attach | 成功连接 |
| schema | 返回表列表 |
| 路径安全 | 越界路径被拦截 |
| fallback | attach 失败不影响 CSV 主流程 |
